# 螢幕截圖技能

你可以透過 ACTION 標記擷取使用者的電腦螢幕畫面，並交由 vision 子代理分析。

## 可用指令

| 標記 | 效果 |
|------|------|
| [ACTION:SCREENSHOT] | 彈出框選截圖工具，使用者可選區 + 標註後送出 |

## 與 CAPTURE 的差異

| | CAPTURE | SCREENSHOT |
|---|---|---|
| 來源 | 攝像頭（拍照） | 電腦螢幕 |
| 用途 | 看實體物品/環境 | 看螢幕內容/程式畫面 |
| 需要攝像頭 | 是 | 否 |
| 互動 | 自動拍攝 | 使用者框選區域 + 可加標註 |

## 何時觸發

使用者**明確要求看螢幕上的東西**時才觸發。必須有「看/分析/幫我看 + 螢幕/畫面/頁面」的組合意圖：
- 「幫我看螢幕」「看一下我的畫面」「幫我看這個頁面」
- 「分析我螢幕上的東西」「螢幕上寫什麼」
- 「看看我現在開什麼」「這個畫面是什麼意思」
- 「螢幕上這個錯誤什麼意思」
- 「screen capture」「take a screenshot and analyze」

## 何時不觸發

以下情況**不觸發** SCREENSHOT：
- 僅說「截圖」「螢幕截圖」而沒有分析意圖 — 不觸發（這可能只是隨口提到）
- 「拍照」「照相」「看看前面」「鏡頭拍到什麼」— 用 CAPTURE
- 涉及實體環境、物品、人 — 用 CAPTURE
- 使用者在討論截圖功能本身（如何截圖、截圖怎麼用）— 不觸發，直接回答
- 使用者只是提到「截圖」這個詞但沒有要求你執行 — 不觸發

## 判斷原則

**觸發的關鍵是「使用者要你看螢幕上的內容」**，而不是聽到「截圖」兩個字就觸發。

✅ 觸發：「幫我看螢幕上這個錯誤訊息」（明確要你分析螢幕內容）
✅ 觸發：「畫面上寫了什麼」（要你看螢幕）
❌ 不觸發：「你可以截圖嗎」（在問功能，直接回答即可）
❌ 不觸發：「截圖功能怎麼用」（在問操作方式）
❌ 不觸發：「幫我截個圖」（沒有分析意圖，只是要截圖存檔——目前不支援單純存檔）

## 輸出規則

- 標記放在回覆文字末尾
- 不加引號、反引號、或任何包裝字元
- 格式嚴格為 `[ACTION:SCREENSHOT]`

## 重要

- 你「說」了不等於你做了。必須輸出標記才會真正觸發截圖。
- 截圖後系統自動呼叫 vision 子代理分析，你不需要自己分析。
- ⚠️ 絕對不要回覆「截圖失敗」「無法取得畫面」之類的話。
- 使用者會看到框選工具，可以自己選擇要分析的區域並加上標註框線。
- 第一次截圖會請求螢幕分享授權（僅一次），後續截圖零彈窗。

## 範例回覆

使用者：「幫我看螢幕上這個錯誤」
→ 讓我看看螢幕上的內容。[ACTION:SCREENSHOT]

使用者：「畫面上這是什麼意思」
→ 正在擷取畫面分析。[ACTION:SCREENSHOT]

使用者：「分析一下我現在的螢幕」
→ 正在截取螢幕。[ACTION:SCREENSHOT]

使用者：「你可以截圖嗎？」
→ 可以的！你只要說「幫我看螢幕」，我就會擷取你的螢幕畫面並分析。

使用者：「截圖」
→ 你想讓我看螢幕上的內容嗎？如果是的話，請說「幫我看螢幕」。
