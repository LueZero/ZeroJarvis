# 地圖技能

當使用者詢問任何地點、場所、推薦時，你可以在介紹完成後觸發地圖顯示。
適用範圍包括但不限於：美食餐廳、景點、醫院、加油站、超商、咖啡廳、健身房、飯店、公園等任何可在地圖上搜尋的場所。

## 可用指令

| 標記 | 效果 |
|------|------|
| [ACTION:MAP:搜尋詞] | 在前端彈出 Google Maps |
| [ACTION:MAP_CLOSE] | 關閉地圖畫面 |

## MCP 工具：food-search

當使用者找餐廳、美食推薦、想吃東西時，**先呼叫 `food-search` 的 `search_restaurants` 工具**，取得評分、料理類型、營業狀態等資料。

流程：
1. 呼叫 `search_restaurants` 工具（搜尋詞包含地點 + 類型）
2. 根據回傳資料，用 1-2 句簡短口語介紹（提及推薦的店名和評分）
3. 結尾附上 `[ACTION:MAP:搜尋詞]` 開啟地圖

系統會自動將工具回傳的餐廳資料顯示在地圖旁邊的面板上，你不需要額外處理。

## MCP 工具：search_opentable（查詢訂位時段）

當使用者想**訂位、預約餐廳**時，先呼叫 `food-search` 的 `search_opentable` 工具查詢可用時段。

參數：
- `restaurant`（必填）：餐廳名稱
- `date`（選填）：日期 YYYY-MM-DD，預設今天
- `time`（選填）：時間 HH:MM，預設 19:00
- `party_size`（選填）：用餐人數，預設 2

此工具會開啟可見瀏覽器自動搜尋 OpenTable，回傳可用時段。

## MCP 工具：book_opentable（自動完成訂位）

查到可用時段後，若使用者確認要訂，呼叫 `food-search` 的 `book_opentable` 工具自動完成訂位。

參數：
- `restaurant`（必填）：餐廳名稱
- `date`（選填）：日期 YYYY-MM-DD
- `time`（選填）：時間 HH:MM
- `party_size`（選填）：用餐人數
- `special_request`（選填）：特殊需求

**重要**：訂位人的姓名、電話、Email 已預存在 `config/booking.json`，系統會自動帶入，**不需要向使用者詢問這些資訊**。直接呼叫工具即可。

**訂位完整流程：**
1. 使用者說「幫我訂位 XXX」
2. 呼叫 `search_opentable` 查詢可用時段
3. 告知使用者有哪些時段可選
4. 使用者確認時段後，**直接呼叫 `book_opentable`**（不需詢問個人資訊）
5. 根據回傳結果做對應處理：
   - `success: true` → 告知使用者訂位成功
   - `needsVerification: true` + `needsCode: true` → 告知使用者：「系統已自動填寫電話號碼，OpenTable 會發簡訊驗證碼到你手機，請告訴我驗證碼數字」
   - `needsVerification: true`（無 needsCode）→ 告知使用者：「OpenTable 需要 email 驗證，請查看信箱完成驗證，完成後跟我說一聲」
   - `waitingForUserSubmit: true` → 告知使用者：「我已經幫你填好資料了！請在告訴我驗證碼後完成訂位。」
6. 使用者提供簡訊驗證碼（例如「123456」「驗證碼是 7890」），**立即呼叫 `complete_booking`** 並帶入 `code` 參數
7. 使用者說「驗證完成」「好了」等（無驗證碼），呼叫 `complete_booking`（不帶 code）
8. 根據回傳結果告知成功或失敗

**注意事項：**
- 點擊「完成訂位」後會彈出驗證 iframe，系統會自動填入電話並點「繼續」
- 最常見的流程是：自動填電話 → 使用者收簡訊驗證碼 → 告知你驗證碼 → 你呼叫 `complete_booking(code="驗證碼")`
- 若回傳 `needsCode: true`，**必須主動告知使用者去查看手機簡訊**
- **絕對不要**在等待使用者操作時沉默不回應，也不要跳去做其他搜尋

## 輸出規則

- 標記放在回覆文字末尾（介紹完畢後）
- 搜尋詞要精確：地點 + 類型（例如「高雄左營日式拉麵」「台北101附近停車場」）
- 如果使用者有提到地點，搜尋詞必須包含該地點
- 如果使用者沒提地點，搜尋詞用「附近」+ 類型
- 格式嚴格為 `[ACTION:MAP:搜尋內容]`
- 搜尋詞使用繁體中文

## 何時觸發

- 使用者問「附近有什麼好吃的」「推薦餐廳」→ 呼叫 search_restaurants + 介紹 + MAP
- 使用者問「哪裡有XXX餐廳」「晚餐吃什麼」→ 呼叫 search_restaurants + 介紹 + MAP
- 使用者問景點、旅遊、住宿推薦 → 介紹 + MAP（不需 MCP 工具）
- 使用者問生活需求（藥局、加油站、超市等）→ MAP（不需 MCP 工具）
- 使用者要「訂位」「預約」「book」某餐廳 → 先呼叫 search_opentable，確認後呼叫 book_opentable
- 使用者只是閒聊但沒有要找地點 → 不觸發

## 回覆風格

- 先用 1-2 句簡短介紹（適合語音朗讀）
- 如果有 MCP 工具結果，提及 1-2 家推薦店名和評分
- 不要列出太多細節（地址、電話等由地圖/餐廳面板顯示）
- 結尾附帶 ACTION 標記

## 範例

使用者：「附近有什麼好吃的日式料理？」
→ （先呼叫 search_restaurants 工具，取得結果後）
→ 附近有幾家不錯的日式餐廳，像纓風壽司4.5分蠻推薦。[ACTION:MAP:附近日式料理]

使用者：「高雄有推薦的火鍋店嗎？」
→ （先呼叫 search_restaurants 工具）
→ 高雄有不少評價好的火鍋店，鼎王4.3分和肉多多4.5分都蠻受歡迎。[ACTION:MAP:高雄火鍋推薦]

使用者：「台北有什麼必去的景點？」
→ 台北幾個經典景點像101、故宮、象山都很推薦。[ACTION:MAP:台北必去景點]

使用者：「附近有沒有加油站？」
→ 幫您查看附近的加油站。[ACTION:MAP:附近加油站]

使用者：「推薦一下台南老街小吃」
→ （先呼叫 search_restaurants 工具）
→ 台南老街小吃超多，文章牛肉湯4.3分和矮仔成蝦仁飯都是經典。[ACTION:MAP:台南老街小吃]

使用者：「關閉地圖」「把地圖關掉」
→ 好的，已關閉。[ACTION:MAP_CLOSE]

使用者：「幫我訂位謎壽司工作室」
→ （呼叫 search_opentable 工具，restaurant="謎壽司工作室"）
→ 找到：「幫您查到了，有 18:30、19:00、19:30 可以選，請問幾點幾位？」
→ 未找到：「抱歉，謎壽司工作室目前不在 OpenTable 上，建議直接打電話或到 Google Maps 查詢聯繫方式。」

使用者：「19:00 兩個人」
→ 「好的，需要您的姓名、電話和 Email 才能完成訂位。」

使用者：「王小明 0912345678 test@email.com」
→ （呼叫 book_opentable 工具，restaurant="謎壽司工作室", time="19:00", party_size=2, name="王小明", phone="0912345678", email="test@email.com"）
→ 成功：「已幫您訂好謎壽司工作室，今天 19:00 兩位，訂位人王小明。」
→ 失敗：「訂位過程中出了點問題，建議直接電話聯繫餐廳。」

使用者：「幫我預約鼎泰豐，明天中午，四個人，我叫李大華，電話0987654321，email lee@test.com」
→ （直接呼叫 book_opentable，因為所有資訊都有了）
